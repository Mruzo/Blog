# Fix Git Pull Error with Build Files

## The Problem
Git is complaining about untracked files in `frontend/build/` that would be overwritten by the merge. These are build artifacts generated by `npm run build`.

## Solution: Remove Untracked Build Files

Since these are generated files, it's safe to remove them. They'll be regenerated when you run `npm run build` after pulling.

### Option 1: Remove Specific Files (Safest)
```bash
# Remove the conflicting files
rm frontend/build/static/css/main.867c5e6c.css
rm frontend/build/static/css/main.867c5e6c.css.map

# Now pull
git pull origin vybz
```

### Option 2: Remove All Untracked Build Files
```bash
# Remove all untracked files in frontend/build/
git clean -fd frontend/build/

# Now pull
git pull origin vybz
```

### Option 3: Stash Everything and Pull
```bash
# Stash all changes including untracked files
git stash push -u -m "Stashing before pull"

# Pull
git pull origin vybz

# Rebuild (don't restore stash - we'll rebuild fresh)
cd frontend
npm run build
cd ..
```

## Recommended Production Deployment Workflow

**Important:** Pull first to get updated requirements.txt, then install dependencies.

```bash
# 1. Remove untracked build files
git clean -fd frontend/build/

# 2. Pull latest changes (this gets updated requirements.txt)
git pull origin vybz

# 3. Activate virtual environment (if not already active)
source vybzenv/bin/activate  # or your venv path

# 4. Install/update Python dependencies
pip install -r requirements.txt

# 5. Run migrations (if any new migrations)
cd vybzapp
python manage.py migrate
cd ..

# 6. Rebuild frontend
cd vybzapp/frontend
npm install  # Update npm packages if package.json changed
npm run build
cd ../..

# 7. Collect static files
cd vybzapp
python manage.py collectstatic --noinput
cd ..

# 8. Restart your web server
# For systemd:
sudo systemctl restart gunicorn
# Or for supervisor:
sudo supervisorctl restart vybz
```

## Why This Happens

The `frontend/build/` directory is tracked in Git (intentionally), but when you run `npm run build` locally, it generates files with new hashes/timestamps. If these files aren't committed, Git sees them as untracked and won't overwrite them during a merge.

The solution is to always rebuild after pulling to ensure you have the latest version.
